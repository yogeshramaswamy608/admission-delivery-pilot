## Which rules came from elsewhere

- **Notification format.** Health Level Seven International (HL7) defines the Fast Healthcare Interoperability Resources Release 4 (FHIR R4) topic-based notification Bundle profile. Its backport guide describes topic identification by canonical address and permits integration-time discovery in R4. The pinned receiver maps its encounter-start address to a named event. H1's validator 7.0.5 reported one informational canonical-lookup finding per fixture. The prior report review and receiver mapping bound the accepted direct baseline. [R4 notification profile](https://hl7.org/fhir/uv/subscriptions-backport/STU1.1/StructureDefinition-backport-subscription-notification-r4.html) · [R4 topic discovery](https://hl7.org/fhir/uv/subscriptions-backport/STU1.1/components.html#subscription-topics-in-r4) · [Receiver mapping](https://github.com/drajer-health/eCRNow/blob/89da654471b651dd70592f371e577fffa3c5f04e/src/main/resources/subscription-topic-named-event.properties#L3)
- **Replay.** The HL7 backport defines an optional `$events` operation with inclusive event-number bounds. Requesting `full-resource` expresses a preference the server can decline. Requiring complete event 3 before running this comparison is the pilot's source qualification rule. [Subscription events operation](https://hl7.org/fhir/uv/subscriptions-backport/STU1.1/OperationDefinition-backport-subscription-events.html) · [Handling errors and replay availability](https://hl7.org/fhir/uv/subscriptions-backport/STU1.1/errors.html)
- **Search.** FHIR R4 defines the `patient` search parameter for Encounter. The pilot seeded four known admissions, searched for this fictional patient's current Encounters and compared them with the observed notices to identify the missing admission. This set comparison can be checked because the patient, admissions and delivery history are controlled. [R4 Encounter search parameters](https://hl7.org/fhir/R4/encounter.html#search)
- **Duplicate response.** eCRNow's pinned database schema defines the unique key over server base URL, patient ID, notification resource ID, resource type and trigger event. The project scorer requires the matching eCRNow HTTP 422, the exact admission key, one retained row and its original successful request identifier. This is an assertion about this receiver. [eCRNow release schema](https://github.com/drajer-health/eCRNow/blob/89da654471b651dd70592f371e577fffa3c5f04e/src/main/resources/db-scripts/4.xx_db_migration_scripts/psql_db_scripts/schema_alterations_and_constraints/notification_context.sql)
- **Test coverage.** Inferno's 0.13.0 release documents that delivery-error handling, recovery and `$events` are outside its coverage. The project added receiver-side checks for the complete admission at the held deadline and after a late or duplicate original. The package uses fhir-candle 2026.708.1348 as the live test source and eCRNow v4.0.4 as the receiver. [Inferno v0.13.0 scope](https://github.com/inferno-framework/subscriptions-test-kit/blob/v0.13.0/README.md#L45-L46) · [Pinned fhir-candle source](https://github.com/FHIR/fhir-candle/tree/f04a1d4bdcf0265eb401b98eb0647a4ff373813e)
